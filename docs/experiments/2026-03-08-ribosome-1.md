**Date:** 2026-03-08

**Initial state:** `ribosome_1` (InitialState #9)
**Parameters:** 100,000 reactions requested, stats every 50 (first 1000) then every 500. Engine halted at reaction 1,957.

## Key differences from endless_duplication

- `collision_rate` is 0 (no collisions at all)
- `break_rate` is 0.001 (vs `1/1000000` in endless_duplication — roughly 1000x higher)
- Only 1 large active molecule + 1 smaller inactive molecule (vs 2 active in endless_duplication)

## Analysis

### Phase 1: Static equilibrium (reactions 1–1500)

The system is remarkably stable. After an initial break event early on (7 species, 252 total by reaction 201), nothing changes for ~1300 reactions. The 2 active reactants maintain exactly 5 grabs and 2 transitions. No new breaks occur, no new species appear. The break rate (0.001) is high enough that breaks are possible, but with `collision_rate=0`, molecules can only interact through transitions and grabs — not random collisions.

### Phase 2: Fragmentation and death (reactions 1501–1957)

Between reactions 1001 and 1501, 3 additional breaks occur (cumulative 9 to 12), creating a third active species. But this is a death spiral: by reaction 1957, all active reactants are gone (0 species, 0 total). The system has 5 inactive species with 250 total molecules — essentially just the ambient pool with no functional machinery left.

### Engine halt

At reaction 1957, the engine gets stuck: with 0 active reactants and `collision_rate=0`, no reaction can occur. The engine loops emitting identical stats without advancing the reaction counter. The Python wrapper eventually fails parsing the output (JSON decode error from the looping output).

## Interpretation

The `ribosome_1` initial state differs critically from `endless_duplication`:

1. **No collisions** (`collision_rate=0`): Molecules can't randomly combine, so the only way to build new structures is through the existing Petri net machinery (grabs + transitions). This makes the system entirely dependent on its initial active molecules surviving.

2. **Higher break rate** (0.001 vs ~1e-6): Despite the 1000x higher break rate, the system survived longer in wall-clock terms because without collisions, there are far fewer total reaction opportunities. But when breaks do hit the active molecules, there's no recovery path.

3. **Single replicator**: Only 1 large active molecule at the start (the second molecule `DDBBAF...` is inactive). Once it breaks, there's no backup.

The result is a system that's very stable until a critical break event destroys the sole replicator, at which point it instantly dies with no possibility of recovery. This contrasts with `endless_duplication` where the system degraded gradually over thousands of reactions.

**Bug note:** The engine should handle the "no possible reactions" state gracefully instead of looping infinitely. This is a potential improvement for the OCaml engine.
